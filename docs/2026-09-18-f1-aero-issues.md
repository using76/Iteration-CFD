# F1 차량 외부공력 해석 세션 — 문제 기록과 남은 과제 (2026-09-17/18)

Alfa Romeo C42 F1 형상을 300 km/h 정상상태로 해석하고 Studio에 시각화하는 동안
실제로 터진 문제들과, 해결됐지만 손봐야 할 것들을 정리한다. 담당자 없음 —
다음에 이 코드를 만지는 사람이 읽는 문서다.

## 해결된 것

### 1. gui_control이 항상 5초 뒤 TIMEOUT (최악의 버그)
웹 스튜디오는 서버의 `ui.command` 프레임을 **받기만 하고 응답하지 않았다**
(applyEvent.ts의 빈 case — "Iteration GUI 셸용" 주석). 허브는 응답을 5초
기다리므로 어시스턴트의 모든 화면 명령이 항상 TIMEOUT으로 끝났고, 모델은
"다시 시도"를 무한 반복했다(사용자가 본 "생각 중"의 정체).

**수정**: `gui/web/src/ws/uiBridge.ts` — 모든 ui.command에 즉시 응답. 할 수 있는
명령(탭·차트·결과·카메라·필드·notify·locale·설정·follow-run·geometry_open/
import_step)은 실제로 적용하고, 나머지는 UNSUPPORTED로 즉시 거절해 모델이
정직하게 답하도록 했다. hello에서 `ui.state`도 보고한다.

**남은 것**: `geometry_part/transform/boolean/save`(화면 편집)과 set_tool,
set_projection, probe, post_screenshot 등은 아직 UNSUPPORTED. split_view,
compare_run 등도 미구현.

### 2. 구버전 창이 pickUi를 독점
`pickUi`가 "가장 최근에 활동한" 클라이언트를 골랐기 때문에, 수정 전 코드로
열려 있던 창이 명령을 계속 받았고 그 창은 응답할 수 없었다.

**수정**: `hub.ts` — **uiState를 보고한 적 있는 탭을 우선 선택**. 보고 없는
창은 아무리 활발해도 (구버전이면) 명령을 받지 못한다.

**운영 수칙**: 코드를 고친 뒤에는 스튜디오 창을 새로고침하라. 이전 개발 서버
인스턴스에서 열린 창은 HMR 연결이 이미 죽어 자동 갱신되지 않는다.

### 3. steady 해석이 샘플 대비 150배 느렸다 (반복당 5초 vs 30ms)
원인 세 가지가 겹쳤다.
- **비직교도 최대 79.2°** 컷셀 → 압력 포아손 행렬 조건수 폭발 → PBiCGStab이
  매 외부반복마다 내부 반복을 수백~1,000회(solver 상한) 소진. 솔버가 경고를
  남기고도 non-orthogonal corrector는 0개로 돌았다.
- **셀 종횡비 4:1** — `big` 프리셋에 단일 n을 쓰며 긴 도메인(33 m)을 x로 나눴다.
- **압력 relTol 0.01 + maxIter 1000** — 내부 반복 상한을 매번 채우는 설정.

**수정(빠른 모드, 28.5초)**: 축별 n이 먹힌다는 것을 발견(`big dir 128 52 41` —
usage 문서에는 단일 `[n]`으로만 적혀 있다. **usage 문서화 필요**) → 셀 종횡비
2:1, 273k 셀 + relTol 0.05 + maxIter 200 + 1차 upwind + 초기장 절반 속도.
4.1M 셀 정밀 모드는 참조용으로 유지한다.

**남은 것**: non-orthogonal correctors 지원, 다중격자 계열 전처리기,
usage에 축별 n 문서화, 격자 수렴 연구(현재 Cd는 수십 % 불확도).

### 4. 재시작하면 발산 — 이전 해가 0/에 남는 문제
솔버는 최종 상태를 `0/`에 **덮어쓴다**. 그 상태(압력장에 M 스파이크 포함)로
다시 돌리면 첫 압력 솔브에서 즉시 NaN. 1,000회 런이 iter 900 부근에서 소리
없이 죽은 것도 이 증상과 함께 나타났다(로그 끊김, 에러 없음 — 원인 미확인).

**수정**: `fast_patch.py`가 p를 균일 0으로 리셋하고 stale `rho`를 삭제.
프리스타인 초기장은 케이스 밖(`cases/f1-quick.pristine/0`)에 보관한다.

**남은 것**: `-restartFrom`/`-writeInterval`의 실제 동작 검증(스냅샷 디렉터리가
관측되지 않았다), 소리 없는 종료 원인 규명(종료 코드 0으로 정상 종료처럼
끝났지만 iter 900 이후 출력이 없었다).

### 5. nvdb 출력이 컷셀 메쉬에서 조용히 스킵된다
`-output nvdb`는 순수 카테시안 메쉬 전용. 컷셀 메쉬에서는 빈 `VDB/` 디렉터리만
남기고 건너뛴다(로그 한 줄뿐).

**운영 수칙**: 컷셀 해석의 산출물은 `vtu`(바이너리, 빠름)+`foam`을 쓴다.
nvdb는 카테시안 복셀 케이스에서만 나온다.

**남은 것**: 스킵 시 사용자에게 보이는 경고로 승격할지 검토. VTU → NanoVDB
변환기(외부) 후보.

### 6. 형상 자체의 문제
- C42 STL은 **워터타이트가 아니다**(열린 엣지 13,854, 비다양류 810) →
  `-permissive`(패리티 투표)로만 분류 가능. 매번 경고가 뜬다.
- 어시스턴트가 만든 프리미티브 차(`car.step`)는 **길이 4 mm** — 단위 정규화
  없이는 쓸 수 없다. 다운로드 모델도 단위가 임의(전장 46.3 유닛)라 실차
  5.5 m로 스케일 변환이 필요했다.

**수칙**: 샘플 형상은 받자마자 (1) 실스케일 변환 (2) 바퀴/접지면이 xy 평면에
오도록 배치 (3) 워터타이트 검사 — 를 먼저 한다.

### 7. 개발 환경 사고들
- `monaco-editor` 설치가 불완전(파일 다수 누끄) Vite 기동 실패 → 패키지 재설치로
  복구. CI에선 `npm ci`가 답.
- 5173을 다른 프로젝트가 점유 / kill 후 Vite 자식이 포트를 홀딩 → 서버 기동
  실패. 재시작 전 리스너 확인 습관.
- **tsx watch가 서버 파일 변경마다 재시작하며 실행 중 어시스턴트 턴을 죽인다** —
  다른 세션이 ontology 파일을 고치는 동안 턴이 여러 번 사망했다(모델이
  "체크포인트 재생 중"이라고 혼동한 이유). 턴이 도는 중에는 서버 코드 편집 금지.
- 이번 세션 내내 GPU에 29개 컴퓨트 프로세스(93%) — 다른 세션·뷰어와 공유 중.
  속도 측정치는 모두 이 조건에서의 값이다.

## 남은 과제 (우선순위 순)

1. **지오메트리 편집 화면화**: geometry_part/transform/boolean/save는
   UNSUPPORTED 스텁. 지오메트리 탭에 파트 가시성·트랜스폼이 필요하면 여기서.
2. **지오메트리 복구**: STL 워터타이트 수리(웰딩/구멍 메우기) 도구 — 있으면
   -permissive 패리티 투표 의존을 없애고 분류 품질이 오른다.
3. **운동량 적자 조사의 지면 경계층 오염**: no-slip 지면이 33 m 도메인에서
   발달한 BL(~0.6 m)이 출구 조사면에 섞인다. 현재는 웨이크 밴드(|y|≤1.8 m,
   z≥0.3 m)로 제한해 완화. 이동 지면(moving ground)이 근본 해법.
4. **점성 항력 직접 적분**: 현재 평판 추정(≈300 N). 벽면 nut과 컷면 면적으로
   계산 가능하면 총 항력 신뢰도가 오른다.
5. **빠른 파이프라인 스크립트의 저장소 편입**: cases/*가 ignore라
   patch_fields.py / drag_post.py / fast_patch.py / build_report.py가 로컬에만
   있다. force-add 또는 tools/로 이동을 결정할 것.
6. **nvdb 스킵 경고 승격 + usage에 축별 n 문서화** (§3, §5).
7. **멀티 세션 운영**: GPU 프로세스 공유 현황 표시(GPU 배지에 이미 비슷한 것
   있음), tsx watch 재시작이 실행 중 턴을 죽이는 것에 대한 경고.
